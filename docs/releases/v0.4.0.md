## Highlights

**Approximate indexes (`INDEX hnsw|ivf`, `QUANT sq8|pq`)** for collections beyond ~100k vectors, where exact search gets slow:

```
VCREATE docs DIM 1024 INDEX hnsw                       # M 16, EF_CONSTRUCTION 100, EF_SEARCH 64
VCREATE logs DIM 384 INDEX ivf QUANT sq8 RERANK 2      # NLIST / NPROBE auto
VSEARCH docs FP32 <query-vector> K 10 EF 128           # per-query override (also NPROBE, RERANK)
```

On 100k × 1024 real embeddings, HNSW (EF_SEARCH 64) reaches recall@10 0.979 at 0.60 ms p50 (0.44 ms with the AVX2 build), about 50× faster than the flat index; recall matches Faiss for every index type ([benchmark](https://github.com/tranbaohieu/lawliet/blob/main/docs/benchmarks/ann-2026-11-16/README.md)). Index kinds and options: [DESIGN §7.1](https://github.com/tranbaohieu/lawliet/blob/main/DESIGN.md#71-kinds-and-options).

**Python package** — the server binary bundled in a wheel, started from a script, notebook or test:

```python
import lawliet                       # pip install <wheel attached to this release>, import lawliet

with lawliet.server() as r:          # fresh in-memory server on a free port, returns redis.Redis
    r.execute_command("VCREATE", "docs", "DIM", 384)
```

## Changes since v0.2.0

- `VCREATE ... INDEX flat|hnsw|ivf` with `M`, `EF_CONSTRUCTION`, `EF_SEARCH`, `NLIST`, `NPROBE`, `QUANT sq8|pq`, `PQ_M`, `RERANK`
- `VSEARCH ... EF n | NPROBE n | RERANK n` overrides per query
- Filtered search on IVF keeps probing cells until K results pass the filter
- `VINFO`: new fields `index_params`, `index_state`, `index_bytes`
- Optional AVX2 + FMA distance kernels (`make build SIMD=1`, uses the experimental `GOEXPERIMENT=simd`; release binaries stay scalar); `INFO server` reports `vector_simd`
- e-means (arXiv 2611.09501) trainer for IVF centroids, internal and not the default yet (Lloyd k-means stays the default; [DESIGN §16.3](https://github.com/tranbaohieu/lawliet/blob/main/DESIGN.md#163-approximate-index-ivf--e-means-vs-hnsw))
- Python package `lawliet-server` (import `lawliet`): `lawliet.start()`, `lawliet.stop()`, `lawliet.server()`, and a `lawliet` command; wheels for the same platforms as the binaries
- Server flag `--exit-on-stdin-eof` (used by the Python package so the server stops with its parent)
- Release notes come from `docs/releases/<tag>.md`; GitHub Actions pinned by commit SHA

Thanks to @dangptpt for the ANN indexes and the Python package.

## Compatibility

- Snapshot format version 3 is written **only** when a collection uses `INDEX hnsw|ivf` or `QUANT`; otherwise files stay version 2. v0.4.0 reads v1–v3. v0.2.x reads files from v0.4.0 that hold only flat collections, and refuses others with an error.
- Indexes are rebuilt from the vectors when a snapshot is loaded (not stored in the file).
- `VINFO` replies have three more fields, appended at the end.
- Default behaviour is unchanged: without `INDEX`, collections use exact flat search.

## Known limitations

- IVF / PQ training runs inside the `VADD` that triggers it and can block it for up to seconds ([TD-2](https://github.com/tranbaohieu/lawliet/blob/main/TECH_DEBT.md)).
- HNSW recall drops slightly under heavy churn ([TD-3](https://github.com/tranbaohieu/lawliet/blob/main/TECH_DEBT.md)).
- Index memory is not counted by `--maxmemory` ([TD-4](https://github.com/tranbaohieu/lawliet/blob/main/TECH_DEBT.md)); `--maxmemory` limits estimated record size, not process memory (TD-1).
- The wheels of this release are not on PyPI yet; install the `.whl` attached to this release (`pip install <file>.whl`). The `lawliet-server` 0.3.0 currently on PyPI was not built from a release of this repository.
